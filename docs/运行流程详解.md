## 1. 启动脚本

**文件**: `run.sh`

```bash
bash clean.sh  # 清理 LeRobot 数据集缓存

python lerobot_record.py \
    --robot.type G1 \
    --dataset.repo_id ymc/eval_g1 \
    --dataset.single_task "Retrieve the bottled ad calcium milk from the table with the right arm." \
    --dataset.push_to_hub False \
    --dataset.episode_time_s 10000000 \
    --policy.type xvla_client \
    --policy.url https://nat-notebook-inspire.sii.edu.cn/.../proxy/8000/
```

**关键参数说明**:
- `--robot.type`: 指定机器人类型（G1）
- `--dataset.repo_id`: HuggingFace 数据集仓库 ID
- `--dataset.single_task`: 任务描述（用于多模态模型的语言指令）
- `--dataset.episode_time_s`: 每个 episode 的最大记录时长（秒）
- `--policy.type`: 策略类型（xvla_client）
- `--policy.url`: 远程策略服务器 URL（启智平台）

**Dataset Features**:
- **观测特征** (`robot.observation_features`):
  - 状态: 左臂姿态(x,y,z,roll,pitch,yaw) + 关节角(7) + 夹爪(1)
  - 状态: 右臂姿态(x,y,z,roll,pitch,yaw) + 关节角(7) + 夹爪(1)

- **动作特征** (`robot.action_features`):
  - 左臂: 位置(x,y,z) + 四元数(qx,qy,qz,qw) + 关节角(7) + 夹爪(1)
  - 右臂: 位置(x,y,z) + 四元数(qx,qy,qz,qw) + 关节角(7) + 夹爪(1)
  - 控制类型: is_eef (0=关节控制, 1=末端执行器控制)

### 6.1 record_loop 详细流程

**文件**: `lerobot_record.py:241-381`

```python
def record_loop(...):
    timestamp = 0
    start_episode_t = time.perf_counter()

    while timestamp < control_time_s:  # 循环直到达到 episode 时长
        start_loop_t = time.perf_counter()

        # ===== 步骤 1: 获取观测 =====
        obs = robot.get_observation()
        obs_processed = robot_observation_processor(obs)

        # ===== 步骤 2: 构建观测帧 =====
        observation_frame = build_dataset_frame(dataset.features, obs_processed, prefix="observation")

        # ===== 步骤 3: 预测动作 =====
        if policy is not None:
            action_values = predict_action(
                observation=observation_frame,
                policy=policy,
                device=device,
                preprocessor=preprocessor,
                postprocessor=postprocessor,
                task=single_task,
                robot_type=robot.robot_type
            )
            act_processed_policy = make_robot_action(action_values, dataset.features)

        # ===== 步骤 4: 处理动作 =====
        robot_action_to_send = robot_action_processor((act_processed_policy, obs))

        # ===== 步骤 5: 发送动作 =====
        _sent_action = robot.send_action(robot_action_to_send)

        # ===== 步骤 6: 保存到数据集 =====
        action_frame = build_dataset_frame(dataset.features, action_values, prefix="action")
        frame = {**observation_frame, **action_frame, "task": single_task}
        dataset.add_frame(frame)

        # ===== 步骤 7: 可视化（可选）=====
        if display_data:
            log_rerun_data(observation=obs_processed, action=action_values)

        # ===== 步骤 8: 精确睡眠，保持 FPS =====
        dt_s = time.perf_counter() - start_loop_t
        precise_sleep(1 / fps - dt_s)

        timestamp = time.perf_counter() - start_episode_t
```

## 10. 关键时序

### 10.1 单个控制周期时序（30Hz = 33.33ms）

```
0ms                                                                  33.33ms
|-----------|-----------|-----------|-----------|-----------|-----------|
│           │           │           │           │           │           │
│ Get Obs   │ Process   │ Predict   │ Process   │ Send      │ Sleep     │
│ (~5ms)    │ Obs       │ Action    │ Action    │ Action    │           │
│           │ (<1ms)    │ (~10ms*)  │ (<1ms)    │ (~2ms)    │ (~15ms)   │
│           │           │           │           │           │           │
│           │           │           │           │           │           │
│           │           │ * 注意    │           │           │           │
│           │           │   这里可能│           │           │           │
│           │           │   直接从  │           │           │           │
│           │           │   缓存取  │           │           │           │
│           │           │   (<1ms)  │           │           │           │
└───────────────────────────────────────────────────────────────────────┘
```

**时间分解**:
- **Get Observation (~5ms)**:
  - `robot_controller.get_motion_status()` - 获取末端姿态
  - `robot.arm_joint_states()` - 获取关节角度
  - `robot.gripper_states()` - 获取夹爪状态
  - `robot_camera.get_latest_image()` × 3 - 获取三个相机图像
  - `resize_center_crop()` × 3 - 图像处理

- **Predict Action (~10ms 或 <1ms)**:
  - 如果 `_last_results` 有缓存: 直接返回 (<1ms)
  - 如果缓存为空:
    - 数据格式转换 (~1ms)
    - HTTP POST 请求到启智平台 (~5-10ms，取决于网络延迟)
    - 响应数据处理 (~1ms)
    - 缓存 action chunk

- **Send Action (~2ms)**:
  - 调用 SDK 的运动控制接口
  - 发送 DDS 消息到机器人控制器

- **Sleep (~15ms)**:
  - 使用 `precise_sleep` 保持 30Hz 频率
  - 实际睡眠时间 = 33.33ms - (Get+Process+Predict+Send)

### 10.2 Action Chunk 使用模式

```
时间轴:
  t=0        t=1        t=2        ...       t=9        t=10       t=11
  │          │          │                    │          │          │
  ▼          ▼          ▼                    ▼          ▼          ▼
┌────────┐ ┌────────┐ ┌────────┐         ┌────────┐ ┌────────┐ ┌────────┐
│ Loop 0 │ │ Loop 1 │ │ Loop 2 │   ...   │ Loop 9 │ │ Loop10 │ │ Loop11 │
└────────┘ └────────┘ └────────┘         └────────┘ └────────┘ └────────┘
    │
    │ _last_results = None
    │
    ├─► 请求 Server
    │   返回: action_chunk[0:10]  # 10 步动作
    │
    ├─► 返回 action_chunk[0] ──────────────────────┐
    │                                               │
    │                                               ▼
    ├─► 返回 action_chunk[1] ─────────────┐        机器人执行
    │                                      │
    │                                      ▼
    ├─► 返回 action_chunk[2] ───┐         机器人执行
    │                            │
    │                            ▼
    │                            机器人执行
    ...
    │
    ├─► 返回 action_chunk[9]
    │   _last_results = None  # 缓存用完
    │
    └─► 再次请求 Server
        返回: action_chunk[10:20]
```

**优势**:
- 减少网络请求次数（每 10 步只请求 1 次）
- 动作序列更连贯（模型可以规划未来轨迹）
- 提高系统响应速度（大部分时间直接从缓存读取）

## 11. 故障排查

### 11.1 常见问题

**问题 1: 相机图像获取失败**
- **症状**: `get_latest_image` 返回 None 或异常
- **原因**: CosineCamera 初始化未完成
- **解决**: 增加 `time.sleep(0.5)` 等待时间，或检查相机连接

**问题 2: 动作执行延迟**
- **症状**: 机器人响应慢，动作滞后
- **原因**:
  - 网络延迟高（请求 Policy Server）
  - FPS 设置过高（计算时间超过周期）
- **解决**:
  - 使用 action chunk 减少请求频率
  - 降低 FPS（如 30 → 20）
  - 检查 Server 响应时间

**问题 3: 数据集保存失败**
- **症状**: `dataset.save_episode()` 报错
- **原因**:
  - 图像写入线程/进程不足
  - 磁盘空间不足
- **解决**:
  - 调整 `num_image_writer_threads_per_camera`
  - 检查磁盘空间
  - 禁用视频编码（`--dataset.video=False`）

**问题 4: 机器人突然停止**
- **症状**: SDK 报错或机器人停止响应
- **原因**:
  - 动作超出关节限位
  - DDS 通信中断
- **解决**:
  - 检查动作边界
  - 重新连接机器人
  - 查看 SDK 日志

## 12. 总结

**整体流程总结**:
1. **启动**: 清理缓存 → 解析参数 → 注册插件
2. **初始化**: 创建 Robot、Policy、Dataset → 连接硬件
3. **主循环**:
   - 每个 episode: 循环（获取观测 → 预测动作 → 执行动作 → 保存数据）
   - 结束后: 重置环境时间
4. **保存**: 编码视频 → 保存到磁盘 → 上传 Hub（可选）
5. **清理**: 断开连接 → 退出

**关键设计**:
- **三层架构**: Robot ↔ Policy Client ↔ Policy Server
- **Action Chunk**: 减少网络开销，提高执行流畅度
- **LeRobot 集成**: 统一的数据格式和工作流
- **可扩展性**: 通过插件系统轻松添加新 Robot/Policy

**性能优化建议**:
- 合理设置 FPS（推荐 20-30Hz）
- 使用 action chunk 减少网络请求
- 异步图像写入（多线程/多进程）
- 启用视频编码以减少存储空间
